> **Status:** ✅ Updated (V1.1 — Implementation Aligned)

> **Last Updated:** August 2026
> Revision notes: V1.1 — Aligns schema with the Order Service implementation. (1) `price` column made nullable to support MARKET orders. (2) `remaining_quantity` changed from a `GENERATED ALWAYS AS` computed column to a regular `DECIMAL` column — the service sets it at creation and decrements it on fills. (3) `idempotency_key UUID UNIQUE` column added per Order Service spec §8. (4) Outbox table updated to use `published_at` pattern (simpler, consistent with other service outboxes).

---

## 1. Purpose

The Order Database stores user orders, execution volumes, tracking states (open, filled, cancelling, cancelled), and transactional outbox queues.

---

## 2. Table Schemas

### 2.1 Table: `orders`
```sql
CREATE TABLE orders (
    id                  UUID            PRIMARY KEY,           -- UUIDv7, generated by service before INSERT
    user_id             UUID            NOT NULL,              -- Logical reference (no FK — cross-service)
    market_id           VARCHAR(20)     NOT NULL,              -- e.g. 'BTC_USDT'; Kafka partition key
    side                VARCHAR(4)      NOT NULL,              -- 'BUY' | 'SELL'
    order_type          VARCHAR(10)     NOT NULL,              -- 'LIMIT' | 'MARKET'
    price               DECIMAL(30,10),                       -- NULL for MARKET orders
    quantity            DECIMAL(30,10)  NOT NULL,
    filled_quantity     DECIMAL(30,10)  NOT NULL DEFAULT 0,
    remaining_quantity  DECIMAL(30,10)  NOT NULL,              -- Regular column: set = quantity at creation, decremented on fills
    status              VARCHAR(20)     NOT NULL,              -- 'OPEN' | 'PARTIALLY_FILLED' | 'FILLED' | 'CANCELLING' | 'CANCELLED'
    idempotency_key     UUID            UNIQUE,                -- Client-supplied; 24h expiry; NULL only on internal/system orders
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);
```

> **Why `remaining_quantity` is NOT a computed column:** The Matching Engine decrements `remaining_quantity` independently in fill events. Using `GENERATED ALWAYS AS (quantity - filled_quantity)` would prevent the service from setting it directly during atomic outbox transactions. The application layer is responsible for keeping `remaining_quantity = quantity - filled_quantity` consistent.

> **Why `price` is nullable:** MARKET orders have no user-specified price — they match against the best available liquidity. Storing `NULL` instead of `0` clearly distinguishes "no price" from a zero-price order.

### 2.2 Table: `outbox`
```sql
CREATE TABLE outbox (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    aggregate_id    UUID        NOT NULL,                 -- = order_id
    event_type      VARCHAR(50) NOT NULL,                 -- e.g. 'OrderCreated', 'OrderCancelRequested'
    payload         JSONB       NOT NULL,
    partition_key   VARCHAR(20) NOT NULL,                 -- = market_id (Kafka partition routing)
    published_at    TIMESTAMPTZ,                          -- NULL = pending; set by outbox publisher after Kafka ACK
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_outbox_unpublished
    ON outbox(created_at) WHERE published_at IS NULL;
```

> **Outbox pattern:** The background publisher polls `WHERE published_at IS NULL ORDER BY created_at ASC` using `SELECT ... FOR UPDATE SKIP LOCKED`. After Kafka acknowledges the event, it sets `published_at = NOW()`. A row is only considered published after Kafka acknowledges it — the publisher retries on failure.

## 3. Query Design & Expected Patterns

### 3.1 Create Order (Transaction)
```sql
BEGIN;

INSERT INTO orders (id, user_id, market_id, side, order_type, price, quantity) 
VALUES ($1, $2, $3, $4, $5, $6, $7);

INSERT INTO outbox (id, aggregate_id, event_type, payload, partition_key) 
VALUES ($8, $1, 'orders.created.v1', $9, $3);

COMMIT;
```

### 3.2 List Orders for User (Keyset Pagination)
```sql
SELECT id, market_id, side, order_type, price, quantity, filled_quantity, status, created_at 
FROM orders 
WHERE user_id = $1 AND (created_at, id) < ($2, $3)
ORDER BY created_at DESC, id DESC
LIMIT $4;
```
*Index support:* Require a multi-column index on `(user_id, created_at DESC, id DESC)` to satisfy the keyset pagination without sorting.

### 3.3 Update Order Executed Match
```sql
UPDATE orders 
SET filled_quantity = filled_quantity + $1,
    status = CASE WHEN filled_quantity + $1 >= quantity THEN 'FILLED' ELSE 'PARTIALLY_FILLED' END,
    updated_at = NOW()
WHERE id = $2;
```
*Index support:* Primary key lookup `WHERE id = $2`.
